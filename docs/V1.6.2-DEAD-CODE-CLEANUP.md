# v1.6.2 development: dead-code cleanup

Date: 2026-09-10. Baseline: v1.6.1 / `0131593d5c09daf1177016e8dac110fee07542a9`.

This is a local development candidate, not a published release. Runtime-support
expansion is paused pending the user's choice. No CommonLib upgrade, runtime
allowlist change, release ZIP replacement, or GitHub publication is part of this
cleanup. MO2 deployment was subsequently authorized and completed as noted below.

## Second-pass confirmed removals

The second pass follows the user's authorization to clean the remaining unused
SFS-owned code without removing working features. Declaration/definition-only
checks included production code, tests, scripts and compatibility sources;
helpers left orphaned by these removals were checked separately.

| Removed code | Reachability evidence | Preserved active path |
|---|---|---|
| `BuildDefaultPlayerCondition`, `BuildDefaultPlayerClause`, `kDefaultConditionColor` | The condition factory had no caller; the clause factory and color were used only by that factory | Built-in/sample condition creation; `kDefaultConditionId` remains for old save migration |
| `RenameConditionReferences` | Declaration and definition only | Current condition editing, stable IDs, graph/name validation and dependency checks |
| `GetReplacementIdentifier` | Declaration and definition only | Actively used `GetFormIdentifier` and armor resolution |
| `FreezeSafetyPrefixFromSelectedCandidate` | Declaration and definition only | Kit grouping/name generation, `IsSelectedCandidateNsfw`, `ToggleSafetyPrefix` and override state |
| `RebuildAutomaticEquipmentVisibilityBindingsForActor` and its orphaned `ClearAutomaticEquipmentVisibilityBindingsForActor` / actor-specific `ClearAutomaticEquipmentStateEvents` overload | No caller entered the rebuild wrapper; the other two helpers had no remaining callers | Global reset, actual equipment-event ledger/reconciliation and actor synchronization |
| `ClearFittingSlotState` | Declaration and definition only | Suppression state pruning and `ClearAllFittingSlotStates` used by serialization/revert |
| `SetFittingOverridesHiddenForActorSlots` | Declaration and definition only | Active per-item/actor/global visibility controls and workbench mutations |
| `DrawWorkbenchEmptyState` and its orphaned `ApplyWorkbenchEmptyDrop` | No caller entered the old empty-table renderer | `DrawWorkbenchTable`, `DrawSlotCreationRow` and conditional-action drop transactions; the active table source is unchanged |
| `BrowserTab::Slots`, `DragSourceKind::SlotCatalog`, old favorite-prefix/remapping/filter branches | The old tab had no selector and no active-tab persistence; the old drag producer was removed with the unreachable slot catalog | All surviving tab values and explicitly numbered drag IDs unchanged; current slot creation/filtering unaffected |
| `showAllSlots` / `catalogShowAllSlots` | Used only by the removed slot catalog and its settings read/write | Current slot filters, direct editing, protected-slot and shield options |

Existing settings JSON containing `catalogShowAllSlots` still loads: the obsolete
key is ignored and omitted on the next settings save. No live user settings file
was edited. Existing favorite keys are not purged. These are removals of an
unreachable catalog's state, not removal of the current workbench slot UI.

## Preservation checks

- Virtual Token and DD source bodies were compared against the baseline after
  removing only the outer build guard and disabled stub branch. Active source
  text matched exactly after line-ending normalization.
- Public API/Papyrus source, armor hook installation, dye implementation, HT2,
  external equipment transactions, serialization/migration, runtime profiles,
  vendored CommonLib and the dependency lock are unchanged.
- The candidate DLL retains all 13 exported names from the v1.6.1 DLL, including
  Grid Costume, external UI control and Dynamic Footprints queries.
- Old save/JSON compatibility and public external-mod interfaces are not
  candidates for deletion merely because a C++ text search has few matches.
- Remaining low-reference helpers are audit candidates, not proof of dead code.
  This pass does not claim an exhaustive whole-program reachability proof.
