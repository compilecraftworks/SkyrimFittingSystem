# v1.7.0 inline-detour initialization fix

## Evidence and cause

Report: SFS 1.6.6, Skyrim SE 1.5.97, UI/hotkey functional but appearance/hiding inactive. [Supplied log](https://pastebin.com/2Dmw1DBj) shows supported runtime selection and successful RaceMenu/IED initialization, followed by E9 at the vanilla-block, worn-mask and custom-skin call sites. Worn-mask and custom-skin installation was skipped. The same conditions remained in 1.6.9, whose regression test intentionally rejected E9. This is a confirmed initialization gap, not proof of every visual symptom's sole cause.

The three logged targets are branch-pool addresses, not enough to identify their owning mod. Wet Function patch v1.2.0 ships WetFunctionEffect.pex and README only; there is no native hook installer in that archive. No change to that optional patch is needed for this fix.

## Ownership and ABI

An E8 target is a callable function. An E9 target may be an inline body that expects the original engine frame and jumps to its own continuation. Calling it would insert a return address and change stack alignment/offsets. Generic function-pointer chaining is therefore invalid.

At the already versioned five-byte engine call sites, a shared generated gate calls the existing ShouldOverrideSkinning predicate. It saves RFLAGS, RAX/RCX/RDX/R8-R11 and XMM0-5, reserves Windows x64 shadow space and preserves 16-byte pre-call alignment. Inactive calls restore everything and tail-jump to the prior target. No provider bytes are rewritten and its continuation is not guessed. Active calls restore entry state and enter the existing SFS body using the original relocated engine function. This policy also covers the predicate's existing HT2 hair-slot-release case, not just registered outfits.

For active calls, the unknown prior inline body is intentionally bypassed: SFS owns the display decision. This is a documented fallback, not full transparent composition with arbitrary external behavior. Another mod's inline-only visual behavior for the same actor may be superseded. DAVE API ownership still avoids the native vanilla-block hook; DAV NOP handling and backend rendezvous are unchanged. Normal E8 engine/IED/opaque-visitor routes retain their prior implementation.

The custom-skin fallback invokes the original engine through the existing display filter, then attaches registered appearances through the existing SE RDI / AE R15 weight-model path. A startup IED-presence flag enables only the existing coalesced, generation-canceled evaluation queue, not direct IED reentry, a scan or a second refresh path. IED absence means no such work. RaceMenu/morph/HH/dye/strip logic and public API layouts are untouched.

Generated gates use fixed-size process-lifetime hook storage and bounded stack space. There is no per-actor registration/history allocation, new worker, poller or persistent node/resource ownership. There is extra predicate work only at E9-owned sites; no in-game performance measurement is claimed.

## Tests and release verification

- Before production changes, the new real inline-JMP provider fixture failed because the E9 custom hook was not installed.
- CustomSkinningRegressionTests extracts the actual gate, wrappers and all five hook installers and executes their emitted x64 code. Engine/provider objects are fakes, not actual game/NIF rendering.
- 40 original SE/AE E8 custom routing cases remain. An additional 2,560 route executions cover custom E9, worn-mask E8/E9 and vanilla E8/E9, SE/AE, IED present/absent, and 128 alternating actor/visibility states per combination.
- Passive inline fixtures require exact RSP, seven volatile GP registers, six XMM registers and flags after a deliberately clobbering predicate. Frame canaries, all vanilla call arguments, registered attachment counts, mask outputs and IED follow-ups are checked. Inline fixtures jump back instead of RET. Unknown unsupported instruction forms remain unpatched.
- Existing concrete-visitor/RTTI protection, nested scopes, exception unwinding, cross-thread isolation, page-boundary chain reads and cyclic-chain rejection remain tested.

All 28 regression executables and source wiring checks passed in release and releasedbg. The SE/AE-only plugin built successfully, reports FileVersion/ProductVersion 1.7.0.0, and retains the same 16 exported names as 1.6.9. Dependencies and their lock file are unchanged. The reusable scripts/verify-v1.7.0-release.ps1 check requires the runtime ZIP to differ from 1.6.9 only in SFSCore.dll, matches the packaged DLL/source/tests/scripts/docs to the workspace, and rejects compiled/private artifacts in the source archive. Logs are local under output/v1.7.0-inline-detour and are not packaged. No reporter-environment or other in-game test is claimed.
