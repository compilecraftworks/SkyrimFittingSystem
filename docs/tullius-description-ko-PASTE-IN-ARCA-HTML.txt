<p>실제 장비의 방어력·인챈트·효과는 유지하면서, 캐릭터에게 보이는 외형만 따로 구성하는 SKSE 기반 외형 시스템입니다. 기본 UI 단축키는 <strong>F6</strong>이며 옵션에서 바꿀 수 있습니다.</p>

<p>플레이어·NPC·팔로워의 등록 외형, 조건, 실제 장비 숨김, 수동 표시 상태와 외부 모드 탈의 상태는 모두 액터별로 분리됩니다. 탈의 연동 방식과 직접 매핑 정책은 전체 액터가 공유하지만, 실제 이벤트 결과와 복원 상태는 해당 액터 FormID에만 저장됩니다.</p>

<p>SFS는 DAVE, 일반 DAV, 둘 다 없는 Skyrim native 표시 환경을 자동으로 구분하면서 같은 작업대와 저장 데이터를 사용합니다.</p>

<p><strong>소스:</strong> <a href="https://github.com/compilecraftworks/SkyrimFittingSystem" target="_blank" rel="external nofollow noopener noreferrer">https://github.com/compilecraftworks/SkyrimFittingSystem</a></p>

<h2>UI와 작업대</h2>

<h3>작업대 기본 영역</h3>

<p>상단 기본 영역은 선택한 액터의 평상시 상태입니다. 왼쪽 <strong>실제 장비</strong>는 인벤토리에 실제로 착용 중인 장비, 오른쪽 <strong>등록 외형</strong>은 SFS가 대신 보여 주는 외형입니다. 실제 장비를 눈 버튼으로 숨겨도 벗지 않으므로 방어력·인챈트·키워드·장비 효과는 유지됩니다. 등록 외형의 눈 버튼은 시각적 결과만 바꾸고 등록 정보는 지우지 않습니다.</p>

<p>조건이 없는 등록 외형은 해당 슬롯의 기본 외형입니다. 적용 가능한 조건 외형이 없거나 모든 조건이 거짓이면 기본 외형으로 돌아갑니다. 기본 실제 장비·등록 외형·개별 눈 상태는 선택한 액터에게만 저장됩니다.</p>

<h3>작업대 조건 영역</h3>

<p>하단 조건 영역은 상황별 표시 규칙을 행으로 구성합니다. 각 행은 왼쪽 <strong>조건 설정</strong>과 오른쪽 <strong>동작 설정</strong>을 독립적으로 보존합니다.</p>

<ul>
<li><strong>조건 설정:</strong> 언제 동작할지 결정합니다. 붙박이 또는 사용자 정의 조건 카드를 놓거나, 조건 탭의 카드를 더블클릭해 첫 번째 빈 조건 카드에 넣습니다.</li>
<li><strong>동작 설정:</strong> 무엇을 어떻게 바꿀지 결정합니다. 실제 장비·기존 등록 외형·새로 등록할 외형을 놓고, 대상 눈 버튼으로 <strong>조건이 참일 때 표시</strong> 또는 <strong>조건이 참일 때 숨김</strong>을 지정합니다.</li>
</ul>

<p><code>+ 조건 슬롯 생성 +</code>은 양쪽이 비어 있는 행을 추가합니다. 조건만 있거나 동작만 있는 행은 안전하게 남아 있으며 반대편이 채워질 때까지 비활성입니다. 한쪽 카드를 지워도 다른 쪽은 지워지지 않고, 양쪽이 모두 비어 있는 행만 UI를 닫거나 다음 로드 경계에서 정리됩니다.</p>

<p>기본 등록 외형은 조건 행의 동작 영역으로 드래그할 수 있습니다. 장비 또는 외형 카드를 컨텍스트 메뉴로 재지정할 때 같은 조건의 빈 동작 행이 있으면 중복 행을 새로 만들지 않고 먼저 재사용합니다. 조건 외형은 같은 액터의 기본 외형보다 우선하며, 여러 조건이 참이면 작업대 행 순서가 우선순위를 결정합니다. 다른 참 행이 우선 중이면 <strong>조건 충족 / 다른 조건 활성</strong>으로 표시됩니다.</p>

<h3>장비 탭</h3>

<p>설치된 ARMO 레코드를 이름·플러그인·슬롯으로 검색합니다. Ctrl을 누른 채 여러 항목을 선택한 후 우클릭하면 일괄 등록할 수 있습니다.</p>

<h3>의상 탭</h3>

<p>OTFT 의상의 방어구 항목을 인벤토리 실제 장비를 착용시키지 않고 한 번에 등록합니다.</p>

<h3>키트 탭</h3>

<p>다중 슬롯 등록 외형과 실제 장비 표시 상태를 재사용 가능한 JSON 키트로 저장하고 적용합니다. 기존 키트 JSON도 호환됩니다. 사용자 키트를 우클릭해 <strong>이름 변경</strong>을 고르면 키트 이름만 바뀌며 파일 경로·조각 구성·저장된 레이아웃은 유지됩니다. 읽기 전용 외부 키트는 변경할 수 없습니다.</p>

<h3>키트 생성기 탭</h3>

<p>설치된 의상 ESP를 선택해 이름·EditorID·점유 슬롯·색상·번호·SMP·노출도 규칙을 기준으로 호환되는 후보군을 구성합니다. 여러 ESP는 CPU와 메모리 예산 안에서 병렬 처리하며, 하나의 선택 ESP는 사용 가능한 작업 예산을 사용합니다. 진행률은 완료된 작업만 누적하므로 병렬 작업 완료 순서 때문에 뒤로 가지 않습니다.</p>

<p>결과 행을 클릭하면 해당 키트를 선택하고 미리보기합니다. Ctrl+좌클릭으로 여러 결과 행을 선택할 수 있으며, 선택한 결과는 이름 변경·항목 삭제·합치기가 가능합니다. 후보 이름을 클릭하면 선택과 읽기 전용 미리보기만 바뀝니다. 조각 교체·삭제 화면은 별도의 <strong>편집</strong> 버튼으로만 들어갑니다. 키보드·게임패드의 위/아래는 현재 목록 선택과 미리보기를 함께 이동하고, 게임의 활성 키는 다음 단계 진입 또는 키트 적용에 사용합니다.</p>

<p>후보 미리보기는 캐릭터와 작업대의 <strong>등록 외형</strong> 열에만 임시로 나타납니다. 저장된 작업대 행·인벤토리·실제 장비는 바꾸지 않습니다. 일반 Skyrim 표시 슬롯 충돌은 그대로 적용되며, 보호 슬롯과 SOS/TNG 성기 장비 후보를 보이게 하는 예외는 이 임시 생성기 미리보기에만 한정됩니다.</p>

<h2>실제 장비·등록 외형 표시와 조건</h2>

<p>실제 장비 숨김은 시각적 처리만 하며 장비를 벗기거나 방어력·인챈트·효과를 없애지 않습니다. 등록 외형 숨김은 표시만 없애고 등록 정보는 보존합니다.</p>

<p>전역 숨김과 개별 눈 버튼은 함께 정상 조합됩니다. 개별 항목이 전역 상태와 다르면 전역 체크박스는 정확한 부분 상태를 보여 줍니다. 외부 모드 자동 상태도 같은 표시 규칙을 따릅니다.</p>

<p>조건 외형은 같은 액터의 기본 외형보다 우선합니다. 조건 카드와 동작 카드는 독립 보존되며, 빈 조건/동작 영역은 같은 드래그 앤 드롭 동작과 시각 스타일을 공유합니다.</p>

<h2>액터와 NPC</h2>

<p>등록 외형·실제 장비 숨김·조건·외부 트랜잭션·임시 표시 상태는 모두 액터별입니다. 액터 선택기는 플레이어·저장 데이터가 있는 NPC·현재 주변 NPC를 표시하며, 적대 액터와 시체는 자동 주변 탐지에서 제외합니다.</p>

<p>모든 액터가 같은 연동 정책과 매핑표를 사용하더라도 실제 결과는 영향받은 FormID에만 저장됩니다. NPC A가 참여한 SexLab 장면이나 복장 교체가 NPC B나 플레이어를 바꾸지 않습니다.</p>

<h2>보호 특수 효과 슬롯과 방패</h2>

<p>50·51·60·61번 슬롯은 기본으로 보호되며 30~61번에서 사용자가 바꿀 수 있습니다.</p>

<ul>
<li>보호 슬롯을 포함한 실제 장비는 항상 표시됩니다.</li>
<li>보호 아이템의 새 등록 외형 등록은 막힙니다.</li>
<li>이미 등록된 기본·조건 외형은 보호 중 비활성이고 보호를 해제하면 돌아옵니다.</li>
<li>장비·의상·키트·조건 등록·탈의 연동 팝업은 같은 필터를 사용합니다.</li>
</ul>

<p><strong>방패를 외형 슬롯으로 사용</strong>은 기본 OFF입니다. OFF이면 실제 39번 방패는 계속 표시되고 방패 외형 등록은 막힙니다. ON이면 39번을 일반 외형 슬롯처럼 쓸 수 있습니다.</p>

<h2>SOS / TNG와 나체 판정</h2>

<p>SFS는 실제 장비와 등록 외형의 최종 표시 조합을 평가합니다. 원본 모드와 사용자가 지정한 노출/가림 정책이 우선하며, SFS가 소유한 런타임 키워드는 안전하게 추적·정리합니다.</p>

<p>자동 32/49번 분류는 원본 ARMO 변경을 최소화합니다. 확인된 32번 상의 전용 아이템은 반대 SFS 소유 Concealing/Covering 상태를 지우고 Revealing 키워드를 얻습니다. 일반적인 32번 전신 장비는 기본 SOS/TNG 32번 동작만으로 가려지므로 SFS는 충돌하는 SFS Revealing 상태만 지우며 Concealing·Covering·Underwear 키워드를 새로 붙이지 않습니다. 분류된 49번 하의는 기본 SOS/TNG가 49번을 자동으로 가리지 않을 수 있어 Concealing/Covering·Underwear 키워드를 얻습니다. ESP·KID·다른 모드가 원래 제공한 키워드는 지우지 않습니다.</p>

<p>32번 상의 전용 이름 판정은 <code>ArmorCuirass</code>·<code>ArmorHeavy</code>·<code>ArmorLight</code>·<code>ArmorMaterial*</code>·<code>ClothingBody</code>·<code>VendorItemArmor</code> 같은 일반 바닐라 장비 분류 키워드를 무시합니다. 아이템 이름·EditorID·의미 있는 모드/KID 키워드는 계속 사용하므로 일반 바닐라 방어구가 <code>top</code>·<code>bra</code>·<code>shirt</code>로 잘못 판정되지 않습니다.</p>

<p>Papyrus와 Skyrim 엔진 조건 <code>WornHasKeyword</code> 검사는 같은 액터별 최종 몸통 표시 상태를 사용합니다. 실제 32번 장비 또는 등록 32번 외형 중 하나가 화면에 보이면 의상을 입은 상태이며, 둘 다 숨겨지면 나체입니다. 이 처리는 인벤토리를 직접 검사하는 외부 DLL만의 별도 로직을 강제로 바꾸지는 않습니다.</p>
