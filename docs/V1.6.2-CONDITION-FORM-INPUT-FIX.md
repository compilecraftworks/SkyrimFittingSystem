# v1.6.2 development: condition form-argument input repair

Date: 2026-09-11. This follows the dead-code cleanup, but is a separate bug fix.
No MO2 deployment, release ZIP replacement, commit or publication was performed.

## Report and confirmed causes

The user relayed that GetInCell argument 1 accepted keystrokes, showed no
suggestions, then returned to blank even for a valid FormID/EditorID.

- CELL suggestions used only the ordinary TESDataHandler form array, omitting
  separately stored interiors and registered exterior/persistent cells.
- Suggestions required an identifier-shaped EditorID. Missing EditorIDs and
  IDs containing punctuation/non-ASCII were discarded; no numeric/stable IDs
  were offered.
- The searchable string dropdown was selection-only. An empty suggestion list
  caused unmatched text to be cleared on loss of focus.
- The lowering parser's typed, assignable and generic form paths accepted
  EditorIDs only. Relaxing the UI alone would not make a FormID executable.
- Editable ObjectRef input could retain the old selected index after typing;
  the caller then restored the old selected value. Unresolved partial text was
  also discarded by its value editor.
- Actor parameters were grouped with TESNPC base records in the parser and
  option collector. The SKSE command list distinguishes Actor arguments (e.g.
  GetDetected, SameFaction) from Actor Base (e.g. GetDeadCount):
  <https://skse.silverlock.org/vanilla_commands.html>.

## Changes and boundaries

1. Added one production form-token resolver used by typed/assignable/generic
   lowering and ObjectRef lookup. It accepts EditorID, hexadecimal FormID
   (with/without 0x), and Plugin.esp|LocalFormID. It uses strict complete numeric
   parsing and preserves the required type checks. Deleted/ignored records are
   rejected. EditorID fallbacks are case-insensitive.
2. CELL collection merges the normal array, interiorCells and a typed snapshot
   of the engine's registered form table. The table snapshot uses its read lock;
   EditorID/po3 callbacks happen after releasing it. This does not load cells or
   walk a streaming world's mutable cellMap from the render thread.
3. Form suggestions include EditorID where available, plugin/local identifiers
   and runtime FormIDs. Lack of an EditorID is no longer exclusion. ActorValue
   options remain names, not form pointers/IDs.
4. Form input is editable with empty or loading suggestions. Typed text no longer
   reuses a stale selected index. Fixed enum dropdown behavior is unchanged.
5. Save-time validation uses the actual lowering parser and required form type.
   Invalid input remains in the draft and a localized EN/KOR/ZH error identifies
   the clause/argument. Valid form arguments are saved as plugin/local IDs when
   available; the Player alias is retained. Existing saved EditorIDs remain
   readable; no bulk migration or user settings edits were performed.
6. Actor uses placed RE::Actor references and the reference UI; ActorBase/NPC
   remain TESNPC records. ObjectRef retains ordinary non-actor references.
7. Save errors no longer disappear one frame later due to unrelated cheap draft
   validation clearing the modal's error text.

The shared repair covers CELL, Location, Race, Class, Faction, Keyword, Global,
Quest, Perk, VoiceType, Weather, Shout, WordOfPower, FormList, SpellItem, Region,
Package, MagicEffect, Scene, AssociationType, Note, EncounterZone, IdleForm,
LocationRefType, ActorBase/NPC, ObjectRef/Actor and the supported mixed/generic
form categories. The condition functions themselves and their game semantics
have not been replaced.

The former duplicate form-ID parsers and identifier-character restriction were
removed, not left as alternate paths. No new persistent global form-pointer
cache was introduced. Full record fallback is disabled in per-frame ObjectRef
editing; it runs for save/lowering resolution instead.

## Remaining validation

These tests do not claim an in-game pass or proof that every Skyrim predicate
works. Test GetInCell/GetInCellParam with installed interior/exterior cells,
GetInCurrentLoc, GetIsRace, GetInFaction, HasKeyword, Actor references and save/load
in the user's actual runtime. Verify no-match errors and first selection with
the complete localized UI. Native/DAV/DAVE game evaluation remains untested here.

At publication, `kChar` was still routed as a numeric argument in the UI/lowering.
The published form-input patch did not fix that separate ABI-sensitive path.
