# SFS 1.6.3: requested runtime and RaceMenu compatibility audit

Date: 2026-09-11. Scope: the requested 1.5.97 and twelve 1.6.x versions,
plus their matching SE/AE RaceMenu distributions. No VR, dependency upgrade,
game/DLL replacement, release packaging or deployment was performed.

## Findings

1. **1.6.678 is an actual support exception.** It is the Epic runtime, identified
   as such in both upstream SKSE and vendored CommonLib's version declarations.
   Official SKSE explicitly does not support Epic. SFS's existing
   `IsSupportedAEVersion` includes 678, but this is only a routing entry, not
   evidence that SKSE can load the plugin. This audit does not remove that entry
   or invent an executable/Address Library fallback. Advertising it as supported
   would be inaccurate. Supporting it requires a working external loader/runtime
   ecosystem, not merely an SFS version-table change.
2. For the other twelve requested game versions, no missing selected relocation
   IDs or missing SFS profile entries were found. This is **not** a full binary
   instruction/ABI or end-to-end gameplay pass for every version.
3. No additional incompatible SFS-used public RaceMenu morph prefix was found
   in the pinned upstream history. Individual historical AE/GOG DLLs remain a
   binary-evidence gap; they are not blocked merely for an unknown package number.
4. The running TAKEALOOK instance logs **SFS 1.6.2**, not the local 1.6.3 repair.
   Its successful initialization cannot verify the new condition-input repair.

## Layout and condition checks

- Build configuration: SE and AE enabled, VR disabled; generated 1.6.3 plugin
  metadata uses Address Library and structure independence. No new game gate.
- SFS core and armor hooks use `runtime/RuntimeLayouts.h`; all requested numbers
  are currently present. Core hooks also validate call instruction prefixes.
  The pre/post-629 profiles currently share hook offsets; that alone does not
  establish equality of complete engine structures.
- Actor/reference runtime-data and actor-state access inspected here use the
  vendored versioned accessors around the 1.6.629 boundary. Renderer device,
  context and swap-chain fields used by SFS precede the changed render-target
  tail; SFS does not index that tail using its compile-time maximum. Dye uses
  the flat RendererShadowState texture slots and D3D11 COM bindings. These
  source checks do not replace validation of each engine binary.
- Function registry and lowering use the loaded native command table. The
  1.6.1170 on-disk metadata confirms graph-variable kChar (00), VM-variable
  kVMScriptVar (4C), and distinct legacy kScriptVar (16), matching the prior
  1.5.97 classification. The fixed command-table bound remains 0x2E0 for this
  supported-family baseline; it must not be assumed safe for a future runtime.
- The Steam executable's on-disk callback code is encoded. It was not treated
  as meaningful disassembly. Process module/path queries did not expose the
  module list in this session, so no new live-code ABI proof was obtained.
  Exact BSFixedString argument ABI evidence remains the prior 1.5.97 inspection
  and shared interface declarations, not a new AE runtime invocation.

## RaceMenu families

Package version, game version, and queried interface version are independent.
The requirement is matching RaceMenu builds on their intended Skyrim runtime,
not running any historical RaceMenu DLL on any game executable.

The source-history audit re-ran successfully: 19 interface/task change snapshots,
including six historical concrete-v3 and thirteen public-v4/v5 snapshots. All
thirteen public snapshots retain the used morph slots. Original concrete-v3
builds target games below the requested 1.5.97 minimum; they are not cast to v4.
The experimental CommonLib RaceMenu port is not a release baseline.

The official files page identifies current Steam/GOG 0.4.20.0 builds for
1.6.1170/1179 respectively; older 0.4.19.16 for 1170, .15 for 1130, .14 for
640 and GOG 659, and .9/.10/.11 for 353. Earlier SE files .11 through .16 are
listed. This is package metadata, not an immutable package-to-source mapping.
Early AE packages for 317/318/323/342/629 and every AE/GOG DLL/re-upload were
not individually obtained. See the full family history and the three hashed
local binary samples in `RaceMenu-Version-Compatibility-v1.6.1.md` and
`RaceMenu-ABI-Audit.md`. Do not present this gap as universal binary verification.
