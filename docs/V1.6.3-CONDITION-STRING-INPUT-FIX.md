# v1.6.3 development: condition string and variable arguments

Status: unreleased, 2026-09-11. The user assigned this repair to **1.6.3**.
The published v1.6.2 archives/tag remain unchanged.

- Implemented: kChar and kVMScriptVar input and condition-owned string lifetime repair.
- GetVMScriptVariable/GetVMQuestVariable use the loaded runtime's native predicates;
  the target remains a typed reference/quest, and argument 2 remains a variable name.
- Legacy kScriptVar callbacks must not be mistaken for functioning Papyrus predicates.
- No MO2 deployment or GitHub publication performed.

## String and VM-variable changes

- `kChar` and `kVMScriptVar` now use an unfiltered, dynamically resized text field, with no integer
  conversion in validation or saving. Numeric-looking names retain leading zeros.
- Lowering supplies a pointer to an owned `RE::BSFixedString` object, NOT a raw
  character buffer, pointer-sized integer, or draft string. A list keeps object
  addresses stable during CNF expansion. An aliasing `shared_ptr<TESCondition>`
  retains the owner until the last evaluator releases it, including after cache
  invalidation. Condition nodes are destroyed before the interned strings.
- Embedded NULs in imported text get a localized validation error instead of
  silently evaluating a truncated name. Lowering independently rejects them.
- No hooks, backend routing, body morphs, dyes, strip links or dependency versions
  changed. Game function availability still comes from the loaded command table.
- The VM argument tooltip explains exact conditional variable names and the
  `::PropertyName_var` backing-name convention in EN/KOR/ZH. Names are not guessed,
  prefixed, converted to FormIDs, or resolved against unrelated scripts.

### ABI evidence and scope

Read-only inspection of the running Skyrim **1.5.97** code (no process writes or
function invocation): `GetGraphVariableInt`, opcode `0x12A3`, RVA `0x2E23A0`,
forwards argument 1 unchanged in RDX to animation-holder vtable slot `0x11`.
`GetGraphVariableFloat`, opcode `0x11BF`, RVA `0x2E2400`, forwards it unchanged to
slot `0x10`. The vendored CommonLibSSE-NG v6.7.0
`IAnimationGraphManagerHolder.h` declares both arguments as
`const BSFixedString&`. This requires an object address, not `c_str()`.
The flat SE/AE interface declaration is shared; this is not a claim of binary or
in-game verification of every AE release.

Additional read-only inspection after the user reopened the main menu:
`GetVMQuestVariable` (opcode `0x1275`, Quest + kVMScriptVar) and
`GetVMScriptVariable` (opcode `0x1276`, ObjectRef + kVMScriptVar) share callback
RVA `0x2D5FF0` in Skyrim 1.5.97. The second argument in R8 is saved in RBP and
passed unchanged as RDX at `0x2D6089` to function RVA `0xC28C80`. That function
loads the interned pointer from `[RDX]`, acquires the pool reference with
`lock cmpxchg [R8-0x10]`, and copies it into the destination fixed-string object.
The callback later releases this local copy via `0xC28D40`. Thus the VM argument
also requires **BSFixedString***, not raw character bytes. The existing owner is
reused; there is no new VM hook, Papyrus invocation or cached variable value.

The actual runtime command table gives `GetScriptVariable` parameter 2 type
`kScriptVar` (0x16), not kVMScriptVar (0x4C) or kChar (0x00).
The old `GetScriptVariable` callback inspected here just returns zero.
This repair exposes the functioning GetVM variants, not a fake implementation
of the obsolete legacy predicates. No automatic numeric-index-to-name conversion
is possible without the original script metadata, so saved expressions are not
silently rewritten to different semantics.
Do not promise all script/quest-variable predicates based on a generic online
parameter table. For comparison, the public [Papyrus Extender condition table](https://github.com/powerof3/PapyrusExtenderSSE/blob/81e4c6b7b4912a3dea6e6be22c31c5e805f69503/src/Papyrus/Util/ConditionParser.cpp)
labels these as kChar but does not implement kChar parsing; it was not used as
proof of their runtime ABI.

## Additional validation repair (included in 1.6.3)

The installed 1.5.97 native command table contains 397 entries with condition
callbacks. kChar occurs in the two graph-variable predicates; kVMScriptVar occurs
in the two VM-variable predicates. The legacy variable type, quest-alias,
package-data and three-argument event predicates remain separate unsupported
paths; an inventory is not proof that all 397 functions execute correctly in SFS.

The three malformed-input inconsistencies found in the follow-up audit are now fixed:
- Numeric editors, draft validation, save normalization and native lowering share
  full-token parsers. Trailing garbage, embedded NULs, integer overflow and
  non-finite/out-of-range native float values are rejected. Valid signed integers
  and native floating-point syntax remain accepted. Invalid existing numeric text
  stays visible in an editable text field instead of displaying a parsed prefix.
- Axis parsing accepts only X/Y/Z (case-insensitive, surrounding whitespace allowed).
  Invalid values produce a validation error and cannot silently lower to Z.
- ActorValue parsing uses the loaded engine's name lookup and preserves its
  uppercase retry. Unknown names cannot lower to kNone (-1). Successful runtime
  values are not restricted by a compile-time enum maximum.
- Choice errors are localized in EN/KOR/ZH. No fallback replaces an invalid value
  with another selection; the user can correct it before saving.

`ConditionValueParsingTests` covers production numeric and axis parsing, including
boundary values and malformed inputs. It also compiles production ActorValue
parsing against a fake engine lookup to verify unknown-name rejection, index zero,
case fallback and runtime-extension acceptance. That lookup test is not an actual
engine execution test. Source-contract checks verify that the UI/save/lowering
paths use the shared parsers.
