# SFS 1.6.6 — game-task query and diagnostic-code audit

Implementation/build verification checkpoint. See RELEASE-NOTES-v1.6.6.md
for the published scope and verification limits; the installed-file hashes
below record the pre-release checkpoint, not current deployment state.

## Inherited fix

The published 1.6.5 query compares the caller's OS thread ID with the last
provider Pump thread ID. That is not a reliable substitute for the SKSE game
task execution context. A subsequent serialized AddTask batch on a different
OS thread can receive WrongThread indefinitely while the provider is idle and
does not schedule another Pump.

The BCNG handoff reproduced this with actual provider/consumer source against
fake engine/task boundaries: legacy Ready on the original thread, legacy
WrongThread on the migrated task including idle retries, task-aware Ready on
that same migrated task. Live TuLED observations showed current Ready snapshots
and notifications but no BCNG apply plan; the live return code itself was not
read. The user reported that the paired local hotfix worked in-game. That is
not verification of all game versions or of this numbered 1.6.6 build.

The original three-file change is retained:

- `src/api/RenderedOutfitProvider.cpp`: one shared QueryImpl and exception
  boundary; a new SkyrimFittingSystem_QueryRenderedOutfitOnGameTask export.
- `extras/SkyrimFittingSystemRenderedOutfitAPI.h`: optional export name and
  caller execution contract. ABI version remains 1, with unchanged statuses,
  POD layouts, function signature, and caller-buffer ownership.
- `tests/RenderedOutfitAPITests.cpp`: legacy guard and task-migration regression
  tests plus the existing availability, lifecycle, IED, and idle-work checks.

Only the task-aware export omits the old last-Pump thread-ID comparison. It does
not queue work automatically and does not verify the caller's execution context
itself. The caller MUST already be executing in SKSE::TaskInterface::AddTask.
Present, input callbacks, arbitrary workers, and concurrent actor-access tasks
are not supported. This explicit precondition is not a universal thread-safe API.

Both entries share argument/header/stride/capacity validation, actor reference
lookup, deleted/disabled/3D checks, readiness recheck under the provider mutex,
root/subscription/suspension handling, and dirty snapshot copying with current
epoch/revision/scene. There is no old-cache fallback or equipment/morph rebuild.

## Consumer migration

1. Resolve the already-loaded SFSCore.dll after SKSE PostPostLoad, never load the
   plugin yourself. Check the v1 API and GetProcAddress for kGameTaskQueryExport.
2. Prefer that export when available. The original query export remains for
   older hosts/clients, with its original last-Pump thread-ID limitation.
3. Keep all reads and apply-time revalidation inside a real AddTask callback.
   A consumer TLS guard is appropriate only when it is scoped to that callback;
   setting a flag on an arbitrary worker does not establish the precondition.
4. Retain current status handling, bounded caller-buffer requery, actor/epoch/
   revision/scene validation, and event-driven coalescing. NotReady/WrongThread
   does not authorize reusing an old outfit or rebuilding SFS display state.
5. No visible torso does not necessarily mean zero items. Non-body accessories
   can remain. Use the relevant effective slots/body flags, not item count alone.

Ready describes the SFS final display decision, not pixel visibility or a fence
for every parallel scene attachment. BCNG's own morph formulas are outside
this SFS change; neither its source nor installed files are edited here.

## Diagnostic/analysis cleanup result

No temporary live probes, OpenProcess/ReadProcessMemory readers, per-frame
diagnostic logger, or diagnostic DLL was introduced into SFS production code
by this handoff. No product code therefore needs deleting for this fix.

- Retain the existing publication-failure error log and IED startup/failure
  diagnostics: these are operational messages, not temporary instrumentation.
- Retain tracked regression tests and generated test fixtures. Test targets are
  separate from SFSCore; their fake engine code does not belong to the DLL.
- RecoveryProbe in stripping/real-equipment transactions is functional timed
  redress recovery, not a diagnostic probe. Removing it would change behavior.
- The handoff's offline readers/probe sources belong to BCNG's ignored build
  audit directory, not SFS source or its packaging inputs. Preserve them and
  original DLL backups; no cross-project cleanup is performed here.
- Existing SFS .tmp/backups/tools artifacts are not attributed to this handoff.
  No broad deletion or cleanup of unrelated historical files is performed.
- A source-wiring regression guard rejects the known temporary probe/read
  identifiers in the API implementation or production XMake target.

## 1.6.6 regression additions and verification scope

- Both exports retain argument checks before any actor lookup, including null
  output, short header, wrong item stride, and zero actor; game-unready queries
  do not touch actors. Task-aware insufficient capacity never partially writes.
- 128 serialized migrated-task transitions cover actual torso, registered
  torso, managed empty, and no torso with a non-body slot-52 item still present.
  Item identity/source, body flags, and effective visible masks are verified.
- Repeated idle retries preserve the legacy WrongThread result without actor
  access. The task-aware path reads the current revision without forcing Pump.
- Existing root/unload/delete/epoch, IED observer/queue, actor isolation and
  coalescing/performance-counter tests are retained. No new polling or timer.
- The build remains SE/AE-only with EXCLUSIVE_SKYRIM_FLAT and VR disabled.
  Exact repository pins remain XMake 3.1.0 and CommonLibSSE-NG 6.7.0 with its
  documented local layout correction; no dependency upgrade.
