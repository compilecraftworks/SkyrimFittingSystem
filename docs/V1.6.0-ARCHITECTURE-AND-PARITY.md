# SFS v1.6.0 Architecture And Feature-Parity Contract

## Release Intent

SFS v1.6.0 is an architecture, integrity, compatibility, and interaction-
reliability release. It starts from the complete v1.5.7 behavior baseline.
Refactoring is not authority to remove, merge, reinterpret, or silently reset a
feature, option, saved state, external integration, or fallback.

The governing order is:

1. explicit v1.6.0 requirements
2. observed v1.5.7 behavior
3. production regression tests and current design documentation
4. earlier release notes, compatibility notes, and commits that explain why a
   boundary or exception exists
5. fail closed and investigate when the intent remains uncertain

Skyrim VR is not a target. All builds remain SE/AE flat-only.

## Required Architecture Boundaries

- UI, Papyrus, and integrations submit typed commands; they do not receive
  unrestricted mutable access to feature state.
- A command validates its complete transition before commit. A failed command
  leaves persistent and runtime state unchanged.
- Actual equipment, registered appearances, conditions, strip transactions,
  dyes, previews, and external suppression retain distinct state ownership.
- Final displayed state is a projection from a stable actor snapshot.
- Nudity, displayed-keyword, footwear, animation, and visual-effect queries all
  consume that same final rendered snapshot. They must not independently infer
  state from equipped forms or mutable workbench rows.
- Runtime effects are actor-local, revisioned, coalesced, and discard stale
  work after actor, load, revert, or lifecycle changes.
- Skyrim runtime layout and each independently versioned RaceMenu interface are
  resolved through compatibility adapters rather than inferred from each
  other.
- Serialization has an explicit schema and tested v1.5.x migration.

### Non-Negotiable Live BodyMorph Boundary

Live BodyMorph for visible registered appearances is a core invariant, not an
optional backend follow-up. `RaceMenuBodyMorph` owns remembered attachment
roots and generation tickets. Only the final display compositor may publish
whether an actor currently has trackable registered appearances. HT2, dye,
camera/pause, conditions, kits, strip/redress, P+, DD, UI, and compatibility
adapters may request an actor refresh but must not clear, replace, or directly
own BodyMorph tracking state.

Every DAVE, DAV, and native refresh publishes actor-local morph eligibility
before backend dispatch. Retained nodes remain remembered when a backend emits
no replacement `OnAttach`; temporary hiding retains update intent and replays
the current morph when visibility returns. Only explicit actor/save lifecycle
teardown may forget tracking state.

The automated gate interleaves equipment/outfit/condition, kit/generator,
protected/shield slot, HT2, dye, paused camera/pose, all four strip modes, P+,
DD, and DAVE/DAV/native refreshes with production BodyMorph tracking. A change
to any of those features fails the release gate if direct and deferred morph
updates no longer reach the retained registered-appearance nodes.

## Feature-Parity Inventory

### UI And Catalog

- Equipment, Outfits, Kits, Conditions, Workbench, Kit Generator, and Options
- search, sorting, scrolling, filters, favorites, inventory-only and unnamed
  equipment filters
- optional actor-local BodyFamily catalog filtering without workbench filtering
- docked and popout-ready catalog hosting
- Ctrl multi-selection and batch registration
- keyboard/gamepad kit navigation
- gear, outfit, kit, and generated-kit previews
- selected actor presentation, pause-safe rotation, camera orbit, character
  side, FOV restoration, and crosshair NPC selection
- fonts, font size, locale, theme, opacity, smooth scrolling, shortcut and
  modifier settings

### Actual Equipment And Registered Appearances

- actor-wide and per-item actual-equipment visibility
- actor-wide and per-card registered-appearance visibility
- condition-driven actual and fitting visibility, including visible-when-true
  and hidden-when-true rules
- independent manual visibility, automatic suppression, temporary manual-show
  exceptions, and appearance locks
- actor-local previews and protected/locked preview behavior
- exact slot/display-mask rules, row order, registration order, and empty
  condition/action rows
- special-effect slot protection, default slots 50/51/60/61, and dedicated
  shield slot 39 enablement
- preservation of actual equipment and condition cards when newly protected
  registered appearances are removed

### Conditions And Drag And Drop

- condition creation, editing, deletion, stable IDs, colors, clauses, CNF,
  function catalog, parameter editors, defaults, validation, lowering, and
  materialization
- nested custom-condition references and circular-reference fail-closed rules
- assignment to actual equipment, fitting appearances, condition rows, and
  conditional visibility rules
- condition/action card creation, movement, replacement, swap, conversion,
  clearing, and deletion
- valid drops commit on the first release exactly once
- all move/swap mutations use stable identities and commit atomically
- sorting, filtering, scrolling, clipping, and deferred workbench order cannot
  redirect a drop to a different row
- invalid or stale payloads fail without clearing either endpoint

### Strip, Redress, And Virtual Tokens

- Mod-Configured Slot Linking
- Automatic Vanilla-Slot Linking
- Direct Editing + Mod-Configured
- Direct Editing + Vanilla
- direct mapping overrides, disabled appearance slots, nested transactions,
  cancellation, redress, recovery, actor isolation, and stale-work rejection
- fixed virtual-token ESL forms and existing save compatibility
- Virtual Worn Tokens become a normal production feature; `PoC` naming and
  conditional-compilation identity are implementation debt, not authority to
  remove the feature
- Devious Devices strip/hider integration is likewise a production adapter
  under `features/devious_devices`; its former `poc` path is not a separate or
  disposable implementation
- the four UI policies are routing choices over one actor-local transaction
  model, not four independently mutable implementations
- SexLab P+ and Devious Devices translate their native/script events into that
  transaction model; they do not own final display, BodyMorph, dye, or backend
  state
- the complete matrix runs on DAVE, DAV, and native: nested strip, reverse or
  missing redress, cancellation, locked/protected cards, player/NPC isolation,
  save transition, and current-morph restoration

### Dye And Rendered Components

- actor/ARMO/exact-rendered-component dye identity
- preview pulse, apply, restore, save/load, and 3D-rebuild restoration
- original DDS, NIF, material, source ARMO, inventory, and actual equipment are
  never modified
- base bodies, hands, anatomical helpers, overlays, and spank/overlay diffuse
  paths remain excluded
- body-family-labelled outfit components remain dyeable
- missing or ambiguous component matches fail closed
- DAVE, DAV, and native display backends retain equivalent dye behavior

### Compatibility And Public Surfaces

- exact supported Skyrim SE/AE runtime profiles and flat vtable layouts
- RaceMenu BodyMorph v4/v5, NiTransform v1/v2 legacy route and v3 public route,
  ActorUpdateManager legacy v0, public-layout v0 backport, and public v1/v2
- actor-local BodyMorph updates, first/third-person roots, bounded completion,
  preview lifecycle, HH_OFFSET synchronization, and stale ticket rejection
- DAVE, DAV, native skinning, Helmet Toggle 2, Grid Inventory, SOS/TNG,
  SexLab P+, Open Animation Replacer, Dynamic Footprints, Wet Function Redux,
  and shipped compatibility-patch boundaries
- the stable external menu C ABI and shortcut-suppression behavior
- settings, favorites, kits, co-save records, Papyrus API, ESL, PEX, packaging,
  locales, and themes
- IED custom-skin routing uses its concrete visitor only on IED's own path.
  When SFS filtering is required at that exact chain, SFS calls the original
  engine visitor with its filter and then queues IED's public actor-level
  `Evaluate`; an unknown early-startup chain fails closed without an ABI cast

## Settings Contract

The v1.5.7 setting keys, defaults, legacy aliases, sanitization, and persistence
remain compatible, including pauseGameWhileOpen, smoothScroll,
menuCharacterSide, addCrosshairNpcToActorList,
catalogBodyFamilyFilterEnabled, specialEffectProtectedSlots,
shieldAppearanceSlotEnabled, every strip-link mode/mapping/override/disabled-
slot value, actor visibility, shortcut, theme, catalog filters, preview mode,
and catalog host mode.

Changing one setting must not mutate unrelated settings or feature state. Pause
mode includes paused preview pose synchronization and physics-safe camera
rotation behavior, not merely the checkbox value.

## Final Rendered Outfit Contract

The final rendered outfit is actor-local and contains two disjoint sources:

- actual equipment that remains visible after global/per-item visibility,
  condition actions, protected-slot policy, external events, and renderer
  compatibility are resolved
- registered appearances that remain visible after global/per-card visibility,
  row conditions, condition actions, automatic suppression, temporary
  strip/redress state, locks, protected-slot policy, previews, and slot
  conflicts are resolved

Body-slot nudity is true only when neither source visibly covers slot 32. A
technically equipped but SFS-hidden body armor does not count as covering the
actor. A visible registered slot-32 appearance does count. Every OAR condition,
the narrow engine `WornHasKeyword` compatibility path, and external displayed-
outfit API must consume this projection rather than reproduce those rules.

## Compatibility Patch Reduction

Patchless integration is preferred, but only where the external owner exposes
a stable provider or event API. SFS must not install a global
`Actor::GetWornArmor` lie or silently rewrite another mod's files.

| Integration | v1.6.0 direction | Remaining external boundary |
| --- | --- | --- |
| Wet Function Redux v1.2.0 patch | Naked auto-apply already uses SFS's narrow final-body engine condition without replacing its MCM. | Its effect script still needs the tiny SFS slot query to apply overlays to body/hand/feet nodes exposed while real armor remains technically worn. Remove only if Wet Function adopts the SFS Papyrus API upstream. |
| Dynamic Feminine Female Modesty Animations v1.4.4 patch | SFS owns the OAR final-outfit conditions, including final slot-32 nudity. | DFFMA's OAR JSON must select those conditions. Keep a data-only config patch until DFFMA ships the SFS conditions itself; globally changing OAR's built-in worn checks is unsafe. |
| Dynamic Footprints v1.4.5 patch | Its host query now reads SFS's canonical final rendered snapshot. | Dynamic Footprints v3.0 has no provider hook, so the verified, fail-closed one-call-site bridge remains necessary. Folding that binary patch into SFSCore would not make it less version-specific. Remove it when Dynamic Footprints exposes or adopts a stable provider API. |

## Feedback Regression Ledger

The all-pages Nexus Posts review and its disposition map are recorded in
`V1.6.0-NEXUS-POSTS-AUDIT.md`. Actionable failures are promoted into
`V1.6.0-FEEDBACK-REGRESSION-LEDGER.md`; intentional behavior is also recorded
so a future fix cannot silently redefine it.

Community and maintainer reports are retained with environment, runtime,
RaceMenu interface versions, display backend, actor, save lifecycle, external
mods, reproduction status, cause, affected invariant, automated coverage, and
in-game verification. Unconfirmed reports remain scenarios; they are not
discarded or silently treated as proven causes.

Priority is data loss/CTD, cross-actor or cross-save leakage, strip/redress and
display inconsistency, condition/UI input loss, compatibility, paused preview,
performance, and usability/localization.

## Change Gates

Every implementation slice must:

1. add characterization or transition coverage before changing ambiguous code
2. preserve stable IDs, actor ownership, save schema, and runtime epochs
3. build the production plugin and all focused tests
4. pass the complete fast regression suite
5. document any behavior difference and obtain explicit approval when it is
   user-visible

Release completion additionally requires the SE/AE, RaceMenu, backend,
player/NPC, pause, preview, strip/redress, condition drag/drop, dye, settings,
save/load, Helgen/early-game IED initialization, and external-integration
in-game matrix. Live BodyMorph after every matrix transition is a mandatory
assertion, not a separate optional case.
