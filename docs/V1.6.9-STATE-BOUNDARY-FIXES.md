# v1.6.9 state-boundary fixes

This supplements the three transaction/queue fixes with five second-audit findings. Reproductions are host tests, not game observations. Test fakes and generated includes never enter SFSCore.dll.

## SOS asynchronous results

Per-actor generations previously restarted when the map cleared. An old VM callback could match a new request for the same FormID; the audit reproduced this in 128/128 host cycles. Use one mutex-protected, process-lifetime uint64 allocator, not reset at map clear. Both callback stages check a pending matching request before unpacking/dispatching; completion checks again under the mutex. Completed callbacks cannot replay and overwrite a result. VM dispatch stays outside the mutex. Cancellation concurrent with check/dispatch may still enqueue a harmless old VM request, but completion cannot publish over replacement state.

Normal pending coalescing, force-after-completion, failed-dispatch retry, Remember/Forget, per-actor caching and SOS-absent no-op remain. The new allocator is one scalar, not a growing history map. SFS does not retain ownership of dispatched VM callbacks.

## Gameplay controls

UI close previously enabled the entire blocked mask. Capture only bits enabled at acquisition and restore only those bits. If storedControls is valid, intersect with its current mask to honor stored-state locks. Never write saved controls or replace the complete enabled state: unrelated changes and externally released pre-existing locks survive. Repeated show/hide and window teardown are idempotent.

Use CommonLib's GetControlsState relocation, not a raw runtime offset or new hook. The gameplay mask, raw input dispatch, mapped Cancel, LT+RS rotation, pause option and character placement are unchanged.

Limit: masks cannot reveal a native plugin's disable request on a bit already disabled by SFS if that plugin does not update stored state. There is no universal inter-mod ownership claim and no invasive ToggleControls detour to guess this case. Actual engine event ordering remains an in-game check.

## Kit paths

Check the final relative key, including existing catalog overwrite keys, before directory creation/file truncation. Reject roots, parent traversal and invalid Windows path components; canonical component containment rejects outside-directory junctions without confusing sibling prefixes. Do not substitute the canonical physical path for the caller's virtual Data path, preserving MO2/USVFS routing.

Nested/Unicode folders, relative dot segments and existing overwrite paths are positive tests. Separate Windows tests created internal and external directory junctions: the former was accepted, the latter rejected. This is pre-write validation, not protection against concurrent malicious filesystem replacement or power-loss-safe atomic persistence.

## Condition store

ID-based references make silently renaming conflicting IDs unsafe. Duplicate definitions, built-in-ID definitions and exhausted signed counters are rejected before store publication/cache invalidation. Normal references TO built-ins, unknown external function names, argument strings, and name disambiguation remain. Normal serialization excludes built-in definitions.

Import staging passes refresh=false to the existing workbench deserializer. Failed condition validation therefore does not queue actor work from the discarded temporary workbench. Successful import still replaces state and refreshes through the existing final path. Malformed cosave fallback policy is unchanged; no-publication claims apply to the parsed condition-store boundary, not arbitrary exceptions after a full import commits.

## Locales and verification

Two actual UI keys missing in kor/zh_cn are restored. All three locales add the invalid-kit-path message. The runner now requires nonempty values for every English key in both other shipped locales.

StateBoundaryTests extracts actual resolver, control adapter, show/hide/shutdown and normalization bodies. Engine/VM/ImGui boundaries are explicit fakes. It covers 128 canceled/replacement cycles, both old callback stages, duplicate completion, independent actors, normal force/retry, SOS absence, callback release, pre-existing/current stored locks, unrelated changes, externally released locks, repeated lifecycle calls and path containment.

ConditionStoreIntegrityTests extracts the actual deserializer and compiles the real built-in definitions. Lookup, cache and display-name helpers are fakes. It covers unchanged store/cache on rejection and normal/reference/unknown-function/sample/empty-list paths. Source checks also enforce no import-stage refresh and path validation before writes.

All 28 targets and source checks passed in release and releasedbg. SE/AE-only DLL built; internal version/export names are verified in release preparation. No dependency, API ABI or backend change; no VR build, diagnostic production code, scan/poll loop, or actual inventory operation. RaceMenu/morph/dye/strip ownership remains unchanged.

Logs: output/state-boundary-fixes/release-regressions.log, releasedbg-regressions.log, build.log. Logs and filesystem fixtures are not distribution contents. Source ZIP includes reusable tests/generators, not generated code or binaries. Verification requires DLL + three locale changes against v1.6.8 and matches packaged source/tests/docs to the workspace.

Not measured: in-game rendering/input, real GPU use, SkyUI time or every external-control combination. The recorded borrowed input-event lifetime and power-loss persistence risks are unchanged. This release does not assert zero possible regressions.
