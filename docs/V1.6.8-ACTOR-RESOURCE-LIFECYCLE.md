# v1.6.8 actor scene-resource lifecycle

Baseline: published v1.6.7 (0d6564b80d0f4216312b56eaa8b3eb2bb9fb9e46).
Scope: two post-release resource-retention findings, not a renderer/backend redesign.

## Boundaries

AppearanceResourceLifecycle subscribes once at DataLoaded to TESObjectLoadedEvent and TESFormDeleteEvent, independently of API subscriptions, RaceMenu presence and IED installation. It never equips, refreshes/rebuilds actors, edits registrations, or scans the world's actors.

| Event | Morph/HH | Dye |
| --- | --- | --- |
| Hide/show, preview, HT2, camera, strip/redress, backend refresh | No new cleanup; existing display owner remains authoritative | Existing behavior |
| Object unload | Drop owned scene nodes/HH roots; cancel this FormID's queued work | Drop owned GPU targets/preview; cancel restore and in-flight builds |
| Object load | Existing native/RaceMenu attachment observer captures new scene | O(1) saved-color lookup; existing bounded restoration only for saved actors |
| Form delete | Also discard activity/attachment eligibility, without actor lookup | Same transient cleanup; no serialized recipe mutation |
| Save load/revert | Existing whole-world tracking/queue reset | Existing clear/load path cancels queue/build work and loads recipes |

Unload intentionally retains **display eligibility flags** (FormIDs only, no scene/GPU pointers). DAVE/RaceMenu can reattach before ObjectLoaded(true) or another SFS refresh; clearing these flags would skip valid first attachments and regress live BodyMorph. Normal display publication owns eligibility, while form deletion/world reset remove it. No per-unloaded-object tombstone map was introduced.

## Queued and in-flight work

- ActorTasks issues monotonic, non-recycled tickets. Erase/reset removes entries without resetting the sequence. Stale completion cannot erase newer work. Actors remain independent.
- Existing HH pending-event coalescing and bounded retries remain. Legacy callbacks validate tickets before continuing or marking synchronization. Already dispatched external Papyrus calls cannot be retracted; SFS stops their subsequent chain. Unload/delete does not edit RaceMenu's internal or other mods' transforms.
- Morph requests already use monotonic actor-local tickets. Real lifecycle cleanup now cancels them and releases morph nodes and HH roots. The unused partial forget helper was removed.
- ActorBuilds tracks only in-flight dye/preview builds and morph/HH attachment observations; independent components do not cancel each other. Completion and unload share the corresponding subsystem mutex. Cancelled builds release their temporary GPU objects instead of republishing; an attachment observer interrupted by unload cannot re-register old scene nodes. Finished/cancelled entries disappear; no historical generation map grows indefinitely.
- Target actor IDs make unrelated unloads avoid walking all tinted components. Unrelated loads schedule no work. The renderer hot-path logic is unchanged.
- Active renderer passes retain their own ComPtr copies until restoring original bindings. Cleanup removes persistent ownership, not references required to restore an in-progress pass safely.
- Saved recipes, API structures and exports are unchanged. No diagnostic probe enters the plugin.

## Verification

All 24 fast regression executables and source guards passed. Tests compile actual production event, cleanup, queue and callback functions with fake engine/provider objects.

- Morph: 128 unload/reload cycles; 128 distinct deleted actors; no residual scene records after deletion; no actor lookup on delete; unload interrupting an attachment/native capture cannot republish old nodes; live morph resumes on reattachment without a new SFS refresh; other actor isolation; existing hidden/preview/HT2/camera/strip cases retained.
- HH: legacy routes 1/2 and public 3/4/synthetic 99; old callback cancellation; immediate same-ID replacement; another actor's pending update. Previous 222 cases retained (232 checks total).
- Dye/events: 128 cycles; saved recipes and other previews preserved; no work for 256 unrelated object loads; bounded unready-scene retries; same-ID queue replacement; counted ownership released after the active pass finishes; last-target dormant flags.
- Concurrent build: worker pauses after beginning a build; unload cancels it; replacement starts; old completion/destruction cannot invalidate replacement. Multiple components and another actor remain independent.
- Source guards verify startup, both events, load restoration, restore-ticket propagation, final dye/preview commit fences and absence of rebuild/equip calls in the lifecycle adapter.
- Existing condition/UI/slot/strip/IED/API/runtime/integration checks remain.

These are host logic/ownership tests, not real D3D allocations, Skyrim event-order emulation, GPU pixel validation, an in-game soak test or proof of zero regressions in all mod combinations. No in-game test or MO2 deployment was performed.

Build uses pinned XMake 3.1.0 and the CommonLibSSE-NG 6.7.0 closure with the documented flat-only local patch. No dependency, VR target, game version, RaceMenu ABI routing or optional patch version changed. Runtime comparison against v1.6.7 permits only SKSE/Plugins/SFSCore.dll to differ.
