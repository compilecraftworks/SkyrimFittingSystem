# v1.6.9: bounded state-preservation fixes

## Baseline and scope

The v1.6.8 audit found three reproducible defects outside the previous 24-test coverage. The two new test executables were first run against unchanged v1.6.8 production functions: both returned failure. Repeated failures are multiple assertions/iterations of those defects, not hundreds of independent bugs.

This note records the first three fixes, limited to `VariantWorkbench.cpp`, `Menu.GridInventory.cpp`, `EquipmentRefreshEventSink.cpp/.h`, and `CoalescedTask.h`. The final release also includes the separately documented [state-boundary fixes](V1.6.9-STATE-BOUNDARY-FIXES.md). No input hook, morph, dye, strip/redress, IED, backend, save schema, or API implementation is changed.

## Condition action transaction

The target setter's boolean conflated invalid input and unchanged input. OR-ing its result with polarity mutation let an invalid target appear successful and clear the source.

The transaction now validates/builds the incoming armor once, stages target and polarity as one operation, and only then reaches existing source cleanup/conflict validation. A polarity-only edit retains existing item metadata; an invalid target returns before either field changes. The public setters used by other UI paths are unchanged. The final original workbench commit/notification remains the only publication point.

`WorkbenchTransactionTests` extracts the real transaction, legacy setters and reset function. It covers protected/missing/catalog-invalid targets, both initial polarities, with/without a source, actual/fitting visibility targets, normal moves, replayed/stale sources, self drops, polarity-only/no-op updates, row-to-rule source cleanup, and late duplicate conflicts. Row conversion implementations not under test abort if accidentally reached; no fake successful conversion masks a failure.

## Grid base appearance ownership

Grid previously reset all player rows, then applied its layout only to base rows. Conditional cards were removed during the first step. The redundant all-player selector and pre-reset are removed. Grid calls the existing `ApplyKitLayout` replacement operation with explicit player base indices.

This uses the existing projection-before-reset guard, locked-card rules, fallback slots and player-local refresh. Global/NPC rows and conditional assignments/cards are not Grid-owned. No Grid binary/script, inventory, saved costume, public message protocol or restored/empty notification policy changes.

The whole Grid adapter body is extracted into the test; catalog/projection/renderer boundaries are explicit fakes. It checks 128 alternating replacements, deduplication, conditional/NPC/global/locked preservation, empty/non-armor/clear no-ops, unusable projection, invalid input and unavailable player/game. This is not a claim that the fake projection validates the game engine's complete kit algorithm.

## Queue ownership and world boundary

The old boolean pending flags could be cleared by a stale callback after replacement work was queued. Condition callbacks also lacked world-generation capture.

Each queue now stores a monotonically allocated ticket and the current pending ticket in two atomics. Cancellation clears only pending ownership; it does not reset the allocator. Completion uses compare/exchange against the exact ticket and cannot release another callback. No map, actor history, heap allocation or retention grows with registrations.

Both producers capture the existing world generation before enrollment and task-interface lookup. A callback must consume its own ticket and match the generation before touching game state. Failed task-interface lookup releases only its own enrollment. Ownership is released before performing the current refresh, as before, so a legitimate change during that refresh can request one follow-up. The existing 500 ms condition interval and actor-local event refresh path are unchanged.

`EquipmentRefreshQueueTests` compiles the real queue class declaration and extracts production enrollment/cancel/dispatch functions. It covers 128 cancellation/replacement boundaries, stale callback replay, both queues remaining independent, unavailable SKSE, unready/ready transitions, cancellation during task-interface lookup, and reentrant current refreshes. Four concurrent producers exercise the ticket helper through another 128 rounds. Barriers make ordering deterministic; this is not a game frame-time benchmark.

## Verification status and limits

The focused tests pass after the fix. All 26 regression executables and source wiring checks passed in both release and releasedbg configurations. The releasedbg SE/AE plugin built successfully with VR disabled; FileVersion/ProductVersion are 1.6.9.0 and all 16 export names match v1.6.8. The only compiler warnings observed were the existing six unused-parameter warnings in vendored CommonLib's Trampoline.cpp.

Initial evidence logs are `output/sfs-1.6.9-regressions.log`, `output/sfs-1.6.9-releasedbg-regressions.log`, and `output/sfs-1.6.9-build.log`. Final combined verification covers 28 targets; see the state-boundary note. `scripts/verify-v1.6.9-release.ps1` requires DLL + three locale changes against v1.6.8, checks corresponding source/build/docs and compares distribution copies. Test/diagnostic binaries and `output/` are not runtime payloads.

No game was launched. The user subsequently requested GitHub publication and ZIPs; MO2/Nexus deployment is not part of that request.

The previous audit's borrowed input-event pointer risk remains separately unverified and unchanged; altering input ownership without a confirmed game-ordering case is outside these three fixes. This release does not claim zero possible leaks/regressions or automatically restore already-deleted cards.
