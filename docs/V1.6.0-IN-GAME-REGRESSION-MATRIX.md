# SFS v1.6.0 In-Game Regression Matrix

This matrix is a release gate, not a list of optional spot checks. Automated
tests protect state transitions and ABI decisions; real Skyrim, RaceMenu,
renderer, animation, Papyrus, and third-party hook timing must still be tested
in game. Record runtime, backend, actor, save, installed integration versions,
steps, expected/observed result, log excerpt, and pass/fail for every run.

## Environment Axes

- flat Skyrim SE 1.5.97
- one verified AE 1.6.317-1.6.353 runtime
- one verified AE 1.6.629+ runtime, including the current 1.6.1170/1.6.1179
  line where available
- DAVE API, DAV without DAVE API, and neither (native)
- RaceMenu BodyMorph v4 and v5; independently exercise NiTransform legacy
  v1/v2 and public v3 where available
- player and one nearby NPC/follower
- new game/Helgen escape, existing save load, save/reload, cell transition,
  actor 3D unload/reload, death/disable where applicable

Unknown Skyrim or RaceMenu layouts must fail closed without installing the
unsafe hook. VR is not a target.

## Clean First Install And Menu Entry

Test a clean MO2 install and a clean Vortex deploy separately:

1. confirm launching `SkyrimSE.exe`/the vanilla launcher does not falsely imply
   that enabling the helper ESL has loaded SFS
2. launch through the runtime-matched `skse64_loader.exe`
3. confirm `Skyrim Fitting System.log` and
   `SKSE/Plugins/SkyrimFittingSystem/settings.json` are created immediately;
   for default MO2 routing, confirm the JSON appears under Overwrite
4. load a save, press F6 once, and confirm the SFS menu opens
5. confirm Skyrim Escape -> Controls has no SFS entry, while
   SFS -> Options -> Toggle UI Button displays F6 and can rebind/reset it
6. repeat after a clean restart using the saved replacement binding

If settings exists but the menu cannot open, capture the exact unsupported
runtime or hook-signature diagnostic from `Skyrim Fitting System.log`. If neither settings
nor the SFS log exists, treat it as an SKSE/native-DLL launch or deployment
failure rather than an SFS keybinding failure.

## Mandatory Assertion After Every Transition

For a morph-enabled visible registered appearance, change a current OBody or
RaceMenu BodyMorph value and confirm the retained first- and third-person
geometry updates immediately. Repeat once without causing a new armor attach.
No HT2, dye, camera, preview, strip, condition, actor switch, or backend action
may disable this assertion. A temporary hidden state may defer the visual write,
but current values must replay when the same appearance becomes visible again.

Also confirm that another actor and a newly loaded save do not inherit the
first actor/save's morph, visibility, dye, strip, preview, or suppression state.

## Core UI And Display

For Equipment, Outfits, Kits, Conditions, Workbench, Kit Generator, and Options:

1. open/close repeatedly with pause off and on
2. switch player/NPC while previewing, filtering, sorting, and scrolling
3. apply and cancel gear, outfit, kit, and generated-kit previews
4. verify camera side, orbit, FOV, zoom, actor facing, and close restoration
5. confirm paused preview has no T-pose and right-drag does not disturb SMP roots
6. verify search, filters, favorites, Ctrl multi-select, keyboard/gamepad
   navigation, locale/font/theme/opacity, and catalog-host settings

Actual equipment and registered appearances must each retain global and
per-card eye states. Exercise manual hide/show, automatic suppression,
temporary manual show, lock, base/conditional rows, condition visibility
actions, and a preview at the same time. Verify default protected slots
50/51/60/61 and shield slot 39 both enabled and disabled.

## Conditions And Drag/Drop

Use long, sorted, filtered, and scrolled tables. On the first mouse release:

- catalog condition to empty condition row and visibility-rule condition card
- condition row to empty row, occupied row, empty rule, and occupied rule
- rule to empty/occupied row and rule
- action card move/conversion separately from condition-card move
- invalid/stale source after deleting or changing the source before delivery
- duplicate/conflicting visibility-rule result

A valid drop commits exactly once. Occupied condition-card drops swap; occupied
action-card drops replace the target and clear the source in the same
transaction. Empty drops move and clear only the source. Invalid, stale, or
conflicting drops change neither endpoint, do not resort to a different visible
row, and emit a diagnostic reason.

## Strip/Redress And Virtual Tokens

Run every row below on player and NPC/follower, then on DAVE, DAV, and native:

| Mode | Base observation | Direct override |
| --- | --- | --- |
| Mod-Configured | Virtual Token/mod slot policy | none |
| Automatic Vanilla-Slot | actual-equipment anchor | none |
| Direct + Mod-Configured | Virtual Token/mod slot policy | mapped and Do Not Link cards |
| Direct + Vanilla | actual-equipment anchor | mapped and Do Not Link cards |

For each mode test ordinary SexLab, SexLab P+ `StripByData`/`StripByDataEx`, and
Devious Devices events where applicable:

- body, hands, feet, head/hair/circlet, shield, and multi-slot appearance
- NoStrip, AlwaysStrip, per-actor P+ overwrite, DD rendered-device visibility
- locked card, protected slot, disabled appearance slot, and direct mapping
- nested strip transactions, reversed redress order, partial/missing redress,
  cancelled scene, DoRedress/victim-redress off, and recovery timeout
- equip/unequip during an active transaction, save/reload during suppression,
  actor switch, and simultaneous player/NPC transactions

The fixed ESL token FormIDs, existing co-save records, Papyrus names, and all
four modes must load from a v1.5.7 save. P+ and DD may translate events only;
they must not mutate BodyMorph, dye, actual inventory, camera, or another
actor's transaction.

## Dye And DDS Filtering

- preview pulse, apply, replace, remove, save/reload, and 3D rebuild restore
- confirm white is displayed as a neutral multiply tint and does not claim to
  whiten a dark source diffuse; `Restore original` removes the saved tint
- same ARMO on two actors; two components with similar names; first/third person
- DAVE, DAV, native; then repeat after HT2, strip/redress, camera preview, and
  BodyMorph changes
- repeat pulse/apply after ENB, Community Shaders, ReShade, or an upscaler has
  replaced the immediate D3D11 context; a verified new context is re-hooked and
  unknown hook ownership fails safely without losing the saved tint
- reject body/hands/feet/anatomy/helper/collision/overlay/spank diffuse targets
- allow legitimate outfit components whose path contains a body-family label
- verify source DDS/NIF/material/ARMO, inventory, conditions, kits, and actual
  equipment remain byte/state unchanged

## HT2, IED, Camera, And Startup

- HT2 show/hide with actual 30/31/42 combinations, pure registered Hair, pure
  Circlet, multi-slot registered headgear, locks, and player/NPC ownership
- no HT2 signal/forms: integration is inert and preserves vanilla/DAVE masks
- new game and Helgen escape with IED installed: inventory/equipment rebuild,
  first SFS registration, cell transition, quicksave/load, player/NPC switch
- confirm no SFS filtering visitor is sent through IED's concrete visitor hook;
  IED receives its deferred actor-level refresh after the engine filter path
- repeat startup with IED absent and with DAVE, DAV, and native
- pause option off/on, repeated menu open, actor switch, replacement preview,
  camera orbit/zoom/FOV, close, load, and cell transition

## Final Outfit And Compatibility Consumers

Build these final visual states: visible actual body only, visible registered
body only, both, technically worn but SFS-hidden actual body, condition-hidden
registered body, unrelated hands/feet only, and temporary strip suppression.
For each, confirm the same answer is observed by SFS nudity, shown armor/keyword
OAR conditions, Wet Function naked/body-hand-feet behavior, DFFMA modesty, and
Dynamic Footprints footwear selection.

Test the three shipped compatibility patches at their exact documented upstream
versions and again without each patch. A missing/mismatched consumer version
must remain unpatched and safe. Patch removal is allowed only after the external
consumer adopts a stable SFS provider/query boundary.

For Wet Function, inspect the installed file conflict list: the patch may win
only `scripts/WetFunctionEffect.pex`. `WetFunctionMCM.pex`, RaceMenu/NiOverride,
Wet Function settings, plugins, and DLLs must remain owned by their original
mods. Save, reload, remove the patch, reload again, and verify that the Wet
Function MCM/settings remain intact.

## Settings, Save, And Packaging

- migrate a v1.5.7 save/settings set, retain all existing keys and aliases
- reset/change one option and verify unrelated options and runtime state remain
- save/reload/revert with conditions, kits, favorites, visibility, dye, strip,
  protected/shield slots, locale/theme, and actor-specific rows populated
- in a minimal profile containing only the runtime-matched Skyrim/SKSE,
  Address Library requirements, and SFS, create a new game, save immediately,
  load that save repeatedly, then return to main menu and load it again; confirm
  no old-world armor, BodyMorph, dye, SOS, token, DD, HT2, or event-sink task
  runs after the load boundary
- verify one `SFSCore.dll`, correct `1.6.0.0` version, Virtual Token ESL and
  Papyrus artifacts, no retired DLL, no VR target, and clean upgrade/uninstall

No release candidate passes while a row is untested, failed, or recorded only
as “seems fine.” Failures are added to the feedback regression ledger before a
fix is accepted.
