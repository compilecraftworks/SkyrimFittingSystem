# v1.7.2 kit integration

This document records the kit/UI integration stage. The final v1.7.2 release
also includes the subsequent [query-cost fixes](SKYUI-QUERY-COST-FIX-2026-09-29.md)
and [heel attachment fix](HH-PENDING-ATTACHMENT-FIX-2026-09-29.md).
Final releasedbg validation on 2026-09-29 passed all 35 native regression
targets, source checks and 11 Python extraction tests. The earlier 33-target
and release-mode results below describe the kit-only stage, not a second-mode
validation of the subsequent fixes. See [release summary](GITHUB-RELEASE-v1.7.2.md).

## Baseline and scope

Integrated the cumulative `1.7.1-community-kit.4` work into official v1.7.1
(`352ac888193536b9f060b5c3e007a524f987f774`). The tag object is not a source
commit; the previous handoff's `375ab84...` identifies the annotated v1.7.1 tag.
The original patch folders and ZIPs are retained outside distribution packages.

The reviewed patch covers 37 files: grouping/candidates, body metadata/list
filtering, three locales, generation/audit tools, tests and XMake targets.
The official integration removes the custom version override and uses VERSION
1.7.2. `scripts/build-kit-integration.ps1` replaces the patch-specific helper.
Normal builds use checked-in reference includes, not private local input files.

No changes are made to native skinning, DAVE/DAV/native backend selection,
virtual strip tokens, DD/P+, RaceMenu/morph/high-heel lifecycle, dye resources,
IED integration, external ABI, helper ESL or Papyrus scripts.

## User-requested list-only behavior

- Favorites Only uses separate Gear/Outfits/Kits values and per-tab cache keys.
  Legacy `catalogFavoritesOnly` seeds missing new values once. New explicit
  false values override the old true preference; invalid fields fall back
  without discarding valid sibling preferences. Save writes only new keys.
  The toggle requests list-only focus and never clears the workbench preview.
  Tests cover all eight saved combinations through 128 cycles, migration,
  malformed fields, active-tab bindings and source wiring. This UI follow-up
  has passed the releasedbg build and full 33-test suite; installed MO2 files
  and previously generated ZIPs are not updated by the source edit itself.
- Equipment/Outfits/Kits share one persisted body-family selection. The old
  automatic actor-family filter is replaced; missing/invalid indices select All.
- Filter changes invalidate only catalog list caches and save the setting.
  The patch's `ClearCatalogSelection()` call on filter change was removed because
  it also cleared the active workbench preview.
- A UI-owned, one-shot `FilterFocus` request selects the first **sorted** result,
  includes it in the ImGui clipper and focuses/scrolls to the row. Empty results
  clear stale list action targets. It owns no engine pointers, jobs or callbacks.
- The filter-confirming input is consumed without applying/previewing a row.
  Actual subsequent mouse/keyboard/gamepad commands use the existing apply and
  preview functions. A focus-only row is not treated as an already previewed
  row when clicked for the first time. Context cleanup resets the focus request.
- Gear/outfit explicit Preview now reaches the selected row even without a
  movement key. Movement and explicit Preview share one existing preview call
  rather than previewing twice on initial movement.
- No body-family compatibility gate is added to apply/preview/workbench paths.
  Existing real-slot protection and item-validity checks are unchanged.

`KitListNavigationTests` exercises the production focus helper through 128
cycles per gear/non-gear case: retained-old-row resets to first, empty results,
one-shot behavior, stale multiselection removal, explicit interaction and reset.
The existing state-boundary harness now contains the actual focus state so its
mechanically extracted production cleanup still compiles and runs.
Source checks enforce the dropdown's limited mutations and all three list
connections. These are host/source tests, not a simulated Skyrim input session.

## Keyboard dispatch and ESP selection follow-up

The existing shared-input hook now reserves the existing 11 keyboard list keys
only in the four navigable tabs, using the same Menu predicate as the command
queue. SFS queues the unfiltered input before dispatch removes those events from
downstream sinks. Text/capture, mapped Cancel, console, pad Activate/Jump and
LT+RS routing retain their existing paths. No new polling or OS hook is added.
On normal close, only the final hold/release of a consumed keyboard press remains
owned. A new down outside SFS always passes, even if the old release was lost;
focus/shutdown resets clear all ownership. This is not a guarantee against mods
that poll keyboard state directly or process input ahead of this hook.

ESP selection remains the generator's existing selected flag. A small visible-row
helper implements Ctrl/ordinary click toggles and Shift range toggles, preserving
hidden selections and using source indices as anchors through sorting. A missing
or filtered anchor falls back to the clicked row; empty results cannot apply a
stale focused plugin. Filtering resets focus to the first visible row. Select/Clear
All operate on visible rows. The optional filter uses a precomputed non-empty ARMA
worn-model-path flag from the existing load-time snapshot, not a per-frame engine
scan; it does not require a body item or alter scan inputs/grouping/preview.
This is evidence of a modeled item, not certification that a plugin is fashion-only
or that the mesh exists on disk. Hidden selected plugins still participate in scans.
The red assessment logic is unchanged, with its criteria exposed in a tooltip.
The warning tooltip is capped at 24 font units of content width (clamped to the
viewport) and expands vertically. EN/KO/ZH-CN use title, criterion and caveat
paragraphs. The existing real-ImGui test checks wrapping, full-height content,
source-window layout isolation, and width bounds at 1600/240-pixel viewports.

`KeyboardInputRoutingTests` mechanically extracts the production filter, context
predicate and dispatch, tests all list keys on all four tabs through 128 close/
reopen cycles each, pre-open holds, missing release, tab/text/capture/console
transitions, mixed event chains, unrelated modifiers and pad routes. It also tests
the production visible-range/model-filter helpers, including hidden/empty rows.
Source guards retain the normal-close call and Shift range wiring.

## Grouping contract

Priority is Modex Community Kit Hub -> ADD screenshot names -> spreadsheet
families -> generic inference. Explicit community compositions stay authoritative
inside candidates, rather than forcing one top-level kit for every version.
All 542 ADD names and the reviewed override file are retained. Photo sequence
numbers do not become guessed design numbers. Related photos may share a pool;
actual distinct designs retain their reviewed boundary.

Generic grouping bridges whole existing name groups using clear EDID outfit
identity plus shared model directories and complementary real slots. It does not
consume recognized parts before preserving existing named accessories. Common
author tags, a shared shoe or male placeholder alone are not merge evidence.
Candidate generation uses the same real-slot/color/style rules for all sources,
retains shared pieces, seeds representative body styles and keeps the 256-profile
cap. Cancellation follows the existing scan worker; no new polling is introduced.

Community family titles remove trailing version annotations (color, length,
number, Roman numeral, weight/physics labels) only from the curated reference
titles, scoped by source plugin. Different semantic titles remain separate.
The unchanged 510 membership references resolve to 262 title families; 360
references belong to 112 multi-version families. This table-wide title count
does not imply that all corresponding mods are installed or runtime-tested.

Each family retains the original membership pools. Candidate generation runs the
existing solver independently for each pool and appends the results with version
labels, reserving a place for every version within the existing 256-candidate
budget. More than 256 explicit versions remain separate groups, rather than
silently discarding versions. Shared accessories remain available in each pool;
no Cartesian mixing between distinct reference versions is introduced.

Generic leading-number families require a shared semantic name, one plugin,
consistent EDID outfit identity and identical complementary real-slot coverage.
They are established before shared model-directory inference can erase their
composition. Subsequent generic merging leaves these already formed versions
intact; community-exclusive pruning also updates the child pools. This uses
scan-local value records, not new persistent engine state or callbacks.

Reanalysis rebuilds generated results. Existing user-created kit JSON files,
workbench appearances and preview/application functions are not migrated or changed.

flat-layout correction, ImGui 1.92.9b, and the upstream transitive lock closure.

Windows SDK 10.0.26100.0. Both Skyrim SE and AE are enabled, VR disabled;
the generator compile guard requires `EXCLUSIVE_SKYRIM_FLAT`.

the exact documented `e36e822129b0fcbdfb51633a7fcee8c76af344bf` pin before packaging;
